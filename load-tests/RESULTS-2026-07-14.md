# Local load-test baseline — 2026-07-14

Environment: macOS arm64, Node 24.18.0, pnpm 11.13.0, k6 2.1.0, backend and load generator on the same machine, in-memory backend storage, no MongoDB, localhost networking. These results do not represent Render production capacity.

## Results

| Scenario | Peak | Result | Key measurements |
| --- | ---: | --- | --- |
| HTTP `/health` | 100 VUs | Pass | 0% failures; p95 5.13 ms; 18,140 req/s; 1,360,534 requests |
| Authenticated REST flow | 100 VUs | **Fail** | 1.52% failures; p95 5.74 s; 31.9 req/s; checks 98.46% |
| WebSocket | 10 connections | Pass | 0 errors; handshake p95 3.65 ms |
| WebSocket | 50 connections | Pass | 0 errors; handshake p95 1.92 ms |
| WebSocket | 100 connections | Pass | 0 errors; handshake p95 1.16 ms |
| WebSocket | 250 connections | Pass | 0 errors; handshake p95 1.04 ms |
| WebSocket | 500 connections | Pass | 0 errors; handshake p95 4.4 ms; 509,928 messages received during the ramp |
| Broadcast | 10 clients / 10 triggers | Pass | 0 missed; latency average 10.8 ms; p95 14 ms |

WebSocket connections were held for 30 seconds in the 10-connection run and 10 seconds in the 50–500 runs. The test reports total sessions opened during each full ramp, not only simultaneous peak connections.

## Backend observations

Before the authenticated REST run, RSS was about 179 MB and event-loop delay p99 was 24.1 ms. After that run, RSS was about 159 MB, event-loop p99 was 105 ms, and the observed maximum delay was 7.56 seconds. The run generated connection resets under peak load.

The authenticated scenario signs in on every iteration. `bcrypt.compare()` is intentionally CPU-intensive, so the result identifies authentication as the first endpoint family to isolate and profile. It does not prove that bcrypt is the only bottleneck.

The final counters after all WebSocket tests were 3,213 opened and 3,213 closed connections, with zero active connections left behind. The cumulative event-loop maximum from the final metrics snapshot is not used because the local machine/session experienced a long scheduling pause between commands; per-run percentiles and the REST post-run snapshot are more meaningful.

## Safe claims

- The local backend completed a staged test with a 500-simultaneous-WebSocket peak without connection errors.
- The 10-client local broadcast test delivered all 10 measured broadcasts, with p95 latency of 14 ms.
- The 100-VU authenticated REST test did not meet the initial SLO and should not be presented as production-ready capacity.
- Production or staging capacity remains unknown until the same tests run from a separate load generator against an authorized staging deployment backed by its production-like database.
